# 모듈 조립 첫 버전

Status: completed
Type: implementation
Updated: 2026-10-08

## 요구와 경계

사용자가 개발 단계를 기록하고 1단계를 진행하도록 요청했다.
기존 Overleaf 기본판과 저널 가이드 조사는 완료돼 있다.
이번 범위는 계층형 조립과 내용 보존이며 일반 article 양식으로 시작한다.
다른 단계의 기능을 이번 구현에 섞지 않는다.

## 확인한 상태

- Git 원격은 연구실 `sunghail/Overleaf_lab`과 공식 upstream이다.
- 기존 Docker 컨테이너와 데이터베이스는 healthy이다.
- 작업 시작 시 추적 파일의 변경은 없었다.
- 사용자 파일인 `paper_template/`와 `.DS_Store`는 이번 변경에 포함하지 않는다.

## 구현 방향

- 모듈마다 고유 식별자와 독립된 본문 파일을 둔다.
- 구조 설정도 프로젝트의 문서로 저장해 기존 저장·이력을 활용한다.
- 조립용 main 문서는 구조와 순서에 따라 생성한다.
- 초기화 시 기존 문서를 덮어쓰지 않는다.
- 숨기기는 출력에서 제외하되 본문과 하위 구조를 보존한다.
- 쓰기 권한을 확인하고 구조 버전이 달라졌을 때 덮어쓰지 않는다.
- 기존 본문 편집기와 PDF 미리보기를 재사용한다.

## 검증 계획

조립 결과, 제목 특수문자, 계층·순서·숨김, 잘못된 구조와 오래된 버전을
검사한다. 브라우저에서 생성·편집·이동·숨김·복원·재접속 및 PDF를 확인한다.

## 구현과 확인 결과

- 기존 CE 편집기의 왼쪽 rail에 `논문 조립` 탭을 추가했다.
- 프로젝트 문서 `lab-assembly.json`에 모듈 ID, 종류, 부모, 순서, 숨김과 버전을 저장한다.
- `lab-module-<UUID>.tex`가 본문 원본이며 `lab-assembled.tex`가 조립 main이다.
- 초기화는 기존 main을 보존한다. 일반 `article`과 최대 3단계 제목 구조로 시작한다.
- 프로젝트 쓰기 권한, 구조 변경 잠금과 버전 확인, 생성 파일 직접 수정 감지를 적용했다.
- 구조 변경 전에 기존 편집기의 미전송 입력이 저장될 때까지 기다린다.
- `node --test services/web/test/lab-assembly/model.test.mjs`: 16개 통과.
- `Module assembly pilot` 브라우저 프로젝트에서 추가, 제목 변경, 버튼 이동,
  실제 드래그 이동, 부모 변경, 부모 숨기기와 복원을 확인했다.
- Data collection을 Methods에서 Results로 옮긴 뒤 PDF 제목과 참조가 2.1에서
  3.1로 바뀌었다. Training의 LaTeX 수식과 본문은 유지됐다.
- PDF 컴파일 성공과 LaTeX 오류 0개를 확인했다.
- ZIP 내보내기에서 초기 main 내용이 바이트 단위로 유지됨을 확인했다.
- 오래된 버전 변경은 409, 비로그인 접근은 401이었다.
- 생성 main을 직접 편집하고 편집기 입력을 저장한 뒤 변경을 요청하면 409로
  차단됐다. 테스트 후 생성 소스와 표시 제목을 복구했다.
- 최종 소스 이미지 재빌드 후 앱·Mongo·Redis 모두 healthy였다. 실제 컨테이너에서
  조립기 테스트 16개와 서버 구문 검사가 통과했다.
- 컨테이너의 새 편집기 소스 SHA-256이 로컬 최종 파일과 일치했다.
- 새 `Module assembly start check` 프로젝트에서 기본 구성이 생성되고 첫 본문이
  Visual 모드로 열리는 것을 확인했다.
- 본문 입력 직후 제목 변경을 요청한 뒤 ZIP에서 내용 보존과 생성 소스 일치를 확인했다.
- 최종 UI에서도 직접 수정한 생성 문서가 보존되고 구조 변경이 차단됐다.
  원래 소스를 복구한 뒤 일반 구조 변경이 다시 가능했다.
- 최종 이미지 재시작 후 pilot 프로젝트의 버전 12와 구성·본문·PDF를 확인했다.
- ego-browser의 스크린샷 API가 응답하지 않아 in-app browser에서 화면을 확인했다.
  새 탭, 모듈 선택, 기존 Visual 편집기와 PDF 배치가 표시됐다.
- CE 실행 이미지는 개발 도구를 제거하므로 별도 ESLint 실행은 도구 부재로
  수행하지 못했다. 프로덕션 webpack 빌드와 실제 브라우저 흐름으로 확인했다.

테스트 프로젝트와 `.local/`의 ZIP·PDF·빌드 로그는 로컬 검증 자료이며 Git에 넣지 않는다.
