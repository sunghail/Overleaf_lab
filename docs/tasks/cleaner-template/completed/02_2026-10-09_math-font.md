# 수식 글꼴 검색 수정

Status: completed
Type: implementation
Updated: 2026-10-09
Base: 92003f7070

사용자가 폰트 오류 여부를 물었다. 재시작 후 최신 검증 원고의 로그에서
`TeX Gyre Termes Math`를 찾지 못하는 실제 fontspec 오류를 확인했다.
이전 PDF 렌더가 정상이어도 재시작 후 컴파일 성공을 보장하지 않는다.
기존 일반 article 원고에는 이 오류가 없으며 Times New Roman 네 파일도 존재한다.

TeX Gyre Termes Math OTF 파일 자체는 설치되어 있지만 Fontconfig 실행 도구와
TeX Live OTF 검색 경로가 없다. Docker 빌드에 Fontconfig 설치·TeX 글꼴 경로 등록·
캐시 생성을 추가한다. 기존 원고의 생성 LaTeX와 사용자 본문은 변경하지 않는다.

완료 기준: 실행 컨테이너가 수식 글꼴을 찾고 재시작 후 원고를 다시 컴파일해
fontspec·글자 누락 오류가 없어야 한다. 새 PDF에서 표 수식과 숫자를 확인한다.

## 확인 결과

수정 이미지 `sha256:0e6b09e7971e946141da9b77c32d9b98b881fb96d33477dd8617327f7fcc5959`로
컨테이너를 재생성한 뒤 `fc-match`가 TeX Gyre Termes Math 및 TeX Gyre Termes를 찾았다.
CLSI·web 상태 응답과 Mongo·Redis·앱 healthcheck가 정상이다.

검증 원고 `6ac75f2096eb1e5598d5a6ca`를 브라우저에서 새로 열고 재컴파일했다.
새 빌드 `1a11c5718f3-db6d22019cdbaac9` 로그의 fontspec 오류 0개,
누락 글자 0개, TeX 오류 0개다. 화면의 Errors·Warnings도 각각 0개다.
원문 로그에는 기존 표의 줄 너비 관련 Overfull 메시지 2개가 남아 있으며 이번 폰트 수정과 별도다.

새 PDF는 5페이지이며 TimesNewRomanPSMT·TimesNewRomanPS-BoldMT·
TeXGyreTermesMath-Regular 글꼴을 포함한다. 표가 있는 2페이지에서 수식 기호와
소수값의 표시를 확인했다. 검증 파일은 `.local/cleaner-template/output/font-fixed.pdf`,
빌드 로그는 `.local/cleaner-template/font-fix-build.log`에 있다.
원고 본문·표 데이터·생성 LaTeX는 변경하지 않았다.
