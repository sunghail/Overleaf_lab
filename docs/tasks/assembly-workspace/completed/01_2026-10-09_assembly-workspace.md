# 독립된 전체 화면으로 논문 조립

Status: completed
Type: implementation
Updated: 2026-10-09
Base: 029f1c1683

사용자는 별도 작은 창·전체 화면·바탕화면 위젯 중 독립된 전체 화면을 선택했다.
편집기 내부 문서·연결 상태 의존성을 화면에서 분리하고 기존 조립 API를 사용한다.
본문 편집은 기존 편집기의 `?doc=<id>` 연결을 사용한다.
원본 원고와 표 내용·권한은 보존한다. 검증은 별도 예시 원고에서 한다.

설계: 공통 조립 위젯, 기존 편집기 연결 컴포넌트, 독립 페이지와 인증된 페이지 경로.
두 화면의 번호·구조 규칙을 별도로 구현하지 않는다. 개인 템플릿으로 만든 새 원고도
독립 조립 화면에서 계속 사용한다. PDF는 기존 컴파일 요청을 사용한다.

미구현 범위: 별도 데스크톱 앱, 항상 위 창, 새 본문 편집 엔진.

## 구현·검증 진행

- 조립 기능을 편집기와 독립 페이지가 함께 사용하는 위젯으로 분리했다.
- 인증과 기존 프로젝트 읽기 권한을 확인하는 전용 페이지 경로를 추가했다.
  쓰기 가능 여부는 기존 권한 검사 결과를 사용한다.
- 원고 구성 카드와 선택한 모듈 설정을 나란히 배치하고 표·템플릿·Word·PDF를 연결했다.
- 자동 화면 테스트 3개 통과: 편집기 Provider 없이 렌더, 기존 문서 열기 콜백 유지,
  읽기 전용 표에서 저장 금지. 로그: `.local/assembly-workspace-tests.log`.
- 브라우저에서 기존 원고를 읽기만 했으며 사용자의 구성 버전 9를 확인했다.
  독립 화면의 템플릿 메뉴로 별도 예시 원고를 만들었고 독립 화면으로 이동했다.
- 검증용 원고: `6ac7cd5aaad9fad48620bb53` (Independent assembly example).
- 첫 빌드 로그: `.local/assembly-workspace-build.log`.
  최종 배치·코드 형식 빌드: `.local/assembly-workspace-release-build.log`.
- 모듈 이동 시 Experiments가 1, 하위 항목이 1.1·1.2로 바뀌었다. 순서를 원래대로 되돌렸다.
- 새 Validation notes 모듈을 추가하고 숨겼다. 표에 `0.12500`·주석을 저장해 버전 6이 됐다.
- Source ZIP 비교에서 기존 일반 본문·서식 자산의 bytes가 모두 같았다.
  변경된 기존 파일은 조립 원문·구성 JSON·표 원문뿐이며 새 모듈과 Word 변환 파일이 추가됐다.
- 본문 링크가 실제 Introduction 본문을 열었다. 기존 편집기 패널도 26개 모듈과
  같은 버전 6을 표시했다. 해당 편집기 창을 닫은 뒤 독립 화면을 계속 사용했다.
- Word 다운로드 버튼 및 직접 응답 검증: HTTP 200, DOCX MIME, 20,972byte.
- 비로그인 GET는 로그인으로 이동했고 조립 화면을 반환하지 않았다.
- 기존 모델 검사 27개도 최종 서버에서 통과했다.
- 최초 PDF iframe은 앱 브라우저에서 빈 화면이었다. 이 접근은 폐기하고 기존 PDF.js
  로더·worker·글꼴 자원을 사용하는 캔버스 미리보기와 페이지 이동으로 교체했다.
  빌드 로그는 `.local/assembly-workspace-pdf-build.log`다.
- 설치된 PDF 엔진의 실제 render API가 `canvasContext`를 요구하는 것을 확인해 연결했다.
  최종 앱 브라우저에서 1/5 페이지의 본문과 2/5 페이지의 표·수식·주석을 직접 확인했다.
  페이지 이동과 미리보기 내부 스크롤도 동작한다. 빈 iframe 접근은 최종 소스에 없다.

## 완료 범위와 재현

편집기 창에 의존하지 않는 인증된 조립 페이지, 모듈·표·템플릿·Word 출력,
PDF 생성·캔버스 미리보기·다운로드, 기존 편집기 문서 연결을 완료했다.
기존 편집기 패널과 저장 규칙을 공유한다. 다른 창에서 구조를 바꿨다면 새로고침하며,
오래된 버전으로 저장하면 기존 충돌 보호 기능이 동작한다.

최종 이미지: `sha256:ade1e214478d618ecba84ee36b752e1d1451406c506cff6fd0fad5e52beee0d7`.
최종 PDF 표시 파일 SHA256:
`0fbd7ccb982926e803b582b4149ff8aa67b461beb3544a317419355b3ce8d643`.
실행 컨테이너와 작업 파일이 일치한다. 최종 빌드 로그는
`.local/assembly-workspace-pdf-release.log`, 화면 기록은 `.local/assembly-workspace-screen.png`다.

사용법: [논문 조립 안내](../../../MODULE_ASSEMBLY.md).
검사 기록: 화면 호스트 3개·기존 모델 27개, 실제 브라우저 흐름과 ZIP bytes 비교.
다중 사용자 동시 편집 전체 시나리오와 새 본문 편집 엔진은 이번 범위가 아니다.
